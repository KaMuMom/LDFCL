# LDFCL 0.6.3

## 旧实例自动关联

旧 `instances/<实例ID>` 目录中没有 `.ldfcl/launch.json`，但实例已保存 `importedVersionId` 时，启动器现在会校验并使用对应的原始版本配置，自动完成隔离迁移。此前加载器实例会提前显示“版本关联信息待确认”，没有执行已有的回退。

启动、选择游戏目录和重新扫描都会执行恢复并保存关联。旧目录保留，复制到唯一的 `versions/<版本文件夹>`；现有存档不合并、不覆盖。迁移完成标记优先用于重试，包括原旧目录后来被删除的情况，避免重复复制或切回原始版本目录。完全没有明确版本记录、配置损坏或目录包含链接时仍保留提示，不按 Minecraft 版本猜测加载器。

## 默认游戏语言

实际写入 `options.txt` 的保存和启动链路，在 `lang` 缺失或空白时补上 `zh_cn`，让新实例默认使用简体中文。已有游戏语言保留；明确的通用语言设置继续生效，实例设置优先于通用设置。

## 未登录默认皮肤

首页及皮肤页在未登录、没有可用账号皮肤时使用内置的经典 Steve。预览无需下载远程纹理；已经登录且有可用皮肤的账号继续显示其外观。纹理来源和版权见 [致谢](../CREDITS.md)。

## GitHub 更新

启动后自动检查 [KaMuMom/LDFCL 的 Latest 正式发行版](https://github.com/KaMuMom/LDFCL/releases/latest)，设置页支持手动检查。发现更新后可在启动器内下载，显示字节进度，校验文件大小、Windows 程序标识与 SHA-256，再点击重启更新。

Windows x64 便携版在退出后替换原 EXE 并重启，旧程序保存在旁边 `.ldfcl-update` 的独立更新文件夹内；不移动或重写 `LDFCL-data` 与 `.minecraft`。游戏运行、下载或其他操作未完成时阻止应用更新。网络失败不阻断启动；开发环境和非便携环境提供检查与发行页入口。

0.6.2 不包含更新检查，需要先手动下载一次本版。今后的正式版本可通过本版的更新入口获取。程序没有 Authenticode 签名，SHA-256 用于核对 GitHub 发行文件的完整性。

## 验证范围

自动测试、最终便携版与源码重建的准确结果见发行资产 `VALIDATION-0.6.3.md`、`verification.json`、`SHA256SUMS-0.6.3.txt`。旧实例恢复使用临时目录、合成文件与真实关联字段的只读副本验证，没有操作用户原始存档；未使用真实 Microsoft 账号或进入 Minecraft 游玩。更新替换以隔离目录和受控程序验证，未来正式版本发布后的跨版本使用仍需实际联网下载。
