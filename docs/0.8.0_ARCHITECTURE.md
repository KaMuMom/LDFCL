# LDFCL 0.8.0 架构与便携路径

## 范围

基于当前 0.7.0 客户端重构模块组织、命令分发、路径解析和构建体系。现有界面和业务算法继续使用原实现：正版设备代码/离线/其他皮肤站登录、多目录与版本隔离、启动及补齐资源、Mod/整合包/资源包/光影包下载、前置和更新、收藏、皮肤库及编辑、Java 与内存、快照、健康检查、诊断、自动更新与桌面快捷方式均保留。

原来的集中式 `core/launcher.ts` 拆成稳定 facade、共享运行时与八个业务域。拆分采用原实现迁移；没有替换认证、下载、游戏启动、存档处理或在线皮肤算法。`src/` 只更换契约包导入，保持上一版现代界面和动效逻辑。所有第三方来源和致谢继续保留在 CREDITS 与 THIRD_PARTY_NOTICES。

## 包和模块

| 层 | 位置 | 责任及依赖 |
| --- | --- | --- |
| 契约 `@ldfcl/contracts` | `shared/` | DTO、选项规则、事件缓冲、命令名称；同时提供 CommonJS 与 ESM |
| 核心 `@ldfcl/core` | `core/` | 全部业务、存储及事务；仅依赖契约与通用库，不导入 Electron |
| CLI `@ldfcl/cli` | `cli/` | 命令行参数及输出；复用核心与契约 |
| 桌面 `@ldfcl/desktop` | `electron/` | 原生对话框、窗口、剪贴板、系统加密、更新与 IPC 适配 |
| React 界面 | `src/` | 页面和交互；通过既有 preload API 调用桌面，只导入契约 |

79 个既有核心命令分别登记在 accounts、appearance、content、directories、downloads、game、storage、system。注册表在初始化时检查未知、重复及遗漏命令；共享的锁、队列、事件、目录事务和生命周期由 `core/runtime.ts` 管理。原请求参数和返回行为延续；部分历史边界仍为 `any`，不能据此宣称所有 RPC 已具备严格类型。

每包独立输出 `dist/` 与声明文件，通过 package exports 解析。根程序入口只加载 `@ldfcl/desktop`；CLI 入口只加载 `@ldfcl/cli`。跨包不再使用诸如 `../shared` 或旧编译目录的引用。旧 `dist-electron` 已停止生成，清理和打包检查仍保留该名称，以拒绝旧文件混入。

## 路径规则

这里的“无路径依赖”指不依赖开发者机器目录、特定盘符、旧安装位置、启动工作目录或某个编译输出层级。应用仍需使用正常的文件路径、系统环境以及用户明确选择的外部目录。

- 便携程序用外层 EXE 的实际目录；未打包桌面用宿主 `app.getAppPath()`。界面与图标用 appPath 下的 `dist/`；preload 是桌面包内相邻文件。
- 默认账号与配置目录是 `<程序目录>/LDFCL-data`；默认游戏根是 `<程序目录>/.minecraft`。CLI 默认以入口所在程序目录定位，不以当前终端 cwd 定位；显式相对命令行路径按终端 cwd 解析仍是预期行为。
- Windows PowerShell 和 Java 探测依据 SystemRoot、ProgramFiles 等实际系统环境与已选数据目录，不写死 C 盘或用户名。源代码包不包含开发机的依赖目录、账号或世界。
- `launcher.json` 增加版本化 `pathBindings`：以 program/data/game 为锚点，记录相对位置和原字段摘要。原绝对字段仍保存，方便旧版读取；新版本搬迁后根据绑定计算当前位置。用户手动改过的字段不被绑定覆盖。
- 程序旁的默认游戏目录、随程序携带的其他目录及自带 Java 跟随整体搬迁；独立放在程序外的游戏根和 Java 保持所选路径。游戏版本 ID、账号选择与目录 ID 不变。
- 旧配置没有绑定时，只有明确默认目录记录且新位置存在真实 `.minecraft` 才关联；不推测或创建丢失的存档。快照增补 Java 相对绑定，旧快照可按已有搬迁历史恢复自带 Java。
- 配置解码不移动、复制或删除用户游戏文件。只移动 EXE 而不带数据，不会自动跨磁盘搜索旧账号/游戏；正常使用应将程序、`LDFCL-data` 和所需游戏目录一起移动。外部游戏目录单独搬家时仍用现有“重新定位”功能。

保留 `versions/<实例文件夹>` 隔离模型，根部 `assets`、`libraries` 共享，实例内 `mods`、`config`、`saves`、`resourcepacks`、`shaderpacks`、`logs` 与 `options.txt` 独立。系统加密没有降低；跨 Windows 用户或设备时应重新登录。Windows 快捷方式依然由系统保存目标位置，整体搬家后旧位置的链接可手动重新创建，启动器继续保护其他安装的同名快捷方式。

## 构建与开发

在任意源码目录执行：

```powershell
npm ci
npm test
npm run build
npm start
npm run dist -- --config.directories.output=release/0.8.0
```

也可从无关目录运行 `node "<源码目录>/scripts/project.cjs" build`。构建工具从自身包定位根目录和编译器，按 contracts → core → cli → desktop → renderer 编译，自动检查模块边界。`build:core` 只构建契约与核心；`build:main` 构建四个非界面包。迁移开发源码后重新执行 `npm ci`，由 npm 重建本地 workspace 链接；发行版不依赖这些开发链接。

`npm run check:architecture` 使用 TypeScript AST 拒绝跨包相对源码引用、未声明的内部依赖、非桌面包导入 Electron，以及开发机用户绝对路径。`scripts/generate-release-report.cjs` 从当前版本与真实报告生成校验摘要，不硬编码测试数量或历史版本。

## 验证与边界

完整测试 420 项包含原 412 项和新增 8 项便携路径/模块边界检查。React、Electron 登录及启动恢复专项继续验证原功能；最终 EXE、源码独立构建、实际两次搬迁的证据由 `release/0.8.0/verification.json` 汇总，详细范围见根目录 VALIDATION。

本次本地构建为 0.8.0，不代表自动改动 GitHub Latest。未进行真实账号授权、在线外观变更或 Minecraft 游玩，未承诺所有低配硬件的最低帧率。
