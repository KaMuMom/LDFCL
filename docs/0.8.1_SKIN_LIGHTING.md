# LDFCL 0.8.1 角色预览修复

## 问题与修正

skinview3d 3.4.2 创建的皮肤与披风纹理未标记为 sRGB。原先流畅模式直接渲染时，又对这些颜色应用了一次 sRGB 输出转换，导致中间调和暗部过亮；视觉优先模式经过后处理却缺少相同的输出转换，两种模式亮度不一致。原环境光强度 3 也使面部层次偏平。

修复集中在 `src/ui/skin-preview-renderer.ts`，首页和衣橱共用：启用正确的颜色管理，将新载入的皮肤、披风和耳朵纹理标记为 sRGB，在渲染前处理更换/编辑后生成的新纹理。直接渲染输出 sRGB；后处理路径在 FXAA 前插入 Three.js OutputPass，只转换一次颜色。

光照改为中性的柔和环境光与位于左上方、随观察相机移动的主光，降低平面泛白感；不启用额外阴影贴图。流畅模式仍只渲染一次场景，静止、隐藏和失焦时的按需绘制逻辑延续，视觉优先保留 FXAA 与像素比上限。输出处理资源在预览销毁时释放。

只调整预览渲染，不修改原始 PNG、皮肤库内容或游戏内亮度设置。账号、实例、下载和启动服务没有变化。

## 验证

`tests/skin-lighting-smoke.cjs` 在真实 React/Three.js 和软件 WebGL 中读取最终画面像素，覆盖首页、衣橱以及中灰、暗部、高光、彩色、纤细皮肤和披风。中灰 128 在旧流畅模式被显示为 184；修正后约为 124，流畅和视觉优先模式的相同部位亮度一致。侧面与正面的明暗差也得到检查。

`tests/skin-preview-performance-smoke.cjs` 继续检查静止零绘制、交互更新、旋转、焦点/可见性暂停、模式切换、经典/纤细模型、皮肤编辑和预览资源释放。最终发行包、源码及验证结果见同版本 release 目录。像素测试使用受控纹理和软件 WebGL，不等同于真实低配硬件或在线皮肤服务验证。
